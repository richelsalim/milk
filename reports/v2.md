# v2 running report

One section per phase (IMPLEMENTATION_V2.md). Every number here comes from a run in
this repo; bench rows land in reports/zoo_baselines.md and are transcribed here.

## Phase V2.0: free budget — snapshots, throughput, recency weights

### Profile of one full-data ple epoch (12-core CPU, torch 6 threads)

| section | wall |
|---|---|
| v1 batch assembly + gathers (276 batches, python per-batch concatenate) | 0.23 s |
| v2 batch assembly + gathers (one vectorized permutation per epoch) | 0.14 s |
| one full epoch incl. setup + 1 val predict + eval | 49.6 s |
| val forward pass (124,909 rows) | 1.3 s |
| one metric evaluation (prepare.evaluate on val) | 0.2 s |

Verdict: batch assembly was never the bottleneck — forward/backward dominates at
~45 s/epoch. The waste v1 actually carried was *redundant forward passes after
training*: the multitask head grid re-predicted validation 16x (~21 s) and snapshot
selection re-predicted for its own scoring. Both now run off the per-epoch validation
prediction cache: selection and the head grid cost metric evaluations only (0.2 s
each), zero extra forwards. A fit-time forward pass now happens exactly once per epoch
(unit-tested).

### Throughput target (>= 8 full-data ple epochs in 300 s): missed, measured best documented

One-epoch walls for the prescribed knobs (1 epoch, full data, head grid off):

| config | epoch wall | primary after epoch 1 |
|---|---|---|
| batch 4096, 6 threads (default) | 47.1 s | 0.6030 |
| batch 8192, lr 2e-3, 6 threads | 45.8 s | 0.6020 |
| batch 4096, 8 threads | 47.5 s | 0.6031 |
| batch 8192, lr 2e-3, 8 threads | 44.5 s | 0.6019 |

The epoch is compute-bound in the model's own matmuls (~12 expert/gate/tower MLPs over
1.14M rows); batch 8192 with scaled lr buys ~5% wall and costs quality at equal epoch
count, extra threads buy nothing (6 physical cores). Measured best on this machine is
~45 s/epoch => ~6 early-stopped epochs inside 300 s, unchanged from v1; the recovered
~25 s of post-fit forwards goes to the snapshot ensemble instead, which reuses the same
6 epochs at zero extra cost. Batch stays 4096, lr stays 1e-3. This is a research
target, not an environment gate — continuing per the guide.

### Snapshot ensembling (snapshot_k=3 default for deepfm/dcnv2/mmoe/ple/din_lite)

Top-3 epochs by cached validation primary, state dicts kept for test-time averaging,
ensemble adopted only when it beats the single best epoch (recorded per fit in
info.snapshot_ensemble).

`python -m recsys.zoo bench --budget 300 --models ple,deepfm` (walls <= 330 s: gate ok):

| model | primary | gauc | ndcg5 | wall | v1 primary | delta |
|---|---|---|---|---|---|---|
| ple | **0.6065** | 0.6743 | 0.5387 | 311 s | 0.6062 | +0.0003 |
| deepfm | **0.6066** | 0.6738 | 0.5393 | 125 s | 0.6057 | +0.0009 |

Research target ple >= 0.6065: hit. The bigger surprise is deepfm: with the top-3
snapshot ensemble it now matches ple at 40% of the wall (125 s vs 311 s) — that
reshapes the V2.2 blend budget math (more room for a third base).

### Recency sample weights (recency_half_life_days, weight = 0.5^(age/half_life))

Grid {None, 3, 7} on ple and lgbm_pointwise; None cells are the fresh v2.0 ple bench
and v1's lgbm_pointwise 0.6012 row (knob-off code path unchanged).

| model | half-life | primary | gauc | ndcg5 | wall |
|---|---|---|---|---|---|
| ple | None | **0.6065** | 0.6743 | 0.5387 | 311 s |
| ple | 7 | 0.6058 | 0.6731 | 0.5385 | 302 s |
| ple | 3 | 0.6042 | 0.6707 | 0.5377 | 209 s |
| lgbm_pointwise | None | **0.6012** | 0.6670 | 0.5354 | v1 row |
| lgbm_pointwise | 7 | 0.5995 | 0.6650 | 0.5340 | 129 s |
| lgbm_pointwise | 3 | 0.5963 | 0.6600 | 0.5326 | 164 s |

Recency-weighted training is uniformly negative here, and monotonically worse as the
half-life shortens — same shape as v1's min_day finding: this 14-day window has no
drift worth paying data for; down-weighting the early week just shrinks the effective
sample. The knob stays in the environment (`recency_half_life_days`, default None
everywhere) as a documented dead end.

### Phase V2.0 outcome

- Snapshot ensembling from cached predictions: default on, gate green, ple 0.6065
  (target hit), deepfm 0.6066 at 125 s.
- Throughput: 8-epoch target missed for physical reasons (compute-bound epoch);
  measured best documented above; freed ~25 s/fit of redundant forwards.
- Recency weights: implemented, benched, rejected as default (kept as knob).
- Tests: +5 in tests/test_v2_models.py (cache-not-forward, torch/lgbm weight effect,
  weight math, determinism with both knobs on); full suite green (gate below).
